**How this curriculum is structured**

The 30 days are split into three phases of ten days each. Phase 1 builds the mental models that make everything else make sense — the memory model, pointers, the heap, and the toolchain. Phase 2 moves into real systems programming: processes, signals, sockets, threads, and hardware interfacing over serial. Phase 3 covers the techniques that separate workable code from production-grade code: high-performance I/O with epoll, lock-free patterns, GDB-based debugging, security-aware coding, and cross-compilation for embedded targets. The capstone on Day 30 wires everything into a complete UART-to-TCP bridge daemon.

**What you're bringing to this**

Your C background and systems intuition from the Python work — especially the MQTT ingestion, binary protocol parsing, asyncio event loops, and serial communication — will compress a lot of Day 1–15. The concepts aren't new; the syntax and the lack of a runtime underneath you are. Expect Days 11–20 to feel like familiar territory approached at a lower level of abstraction.

**How to use this**

Click any day card and hit the "Start Day N" button to begin that lesson. You can go sequentially or jump to whatever's most relevant. Each lesson follows the same format: core concept with real-world grounding, code you can actually run, and a practical exercise you work through independently.

When you're ready, click Day 1 to begin.
